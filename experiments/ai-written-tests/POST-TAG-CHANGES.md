## Transcript sanitising (supersedes the README wording)

The tagged README says `lab/sanitize-transcripts.sh` replaces only the lab path. Since the change above it replaces, in every `*.jsonl` (the stream-json transcript and the session copy): the lab path (`<lab>`), its dashed form in Claude Code's project folder names (`<lab-dir>`), the home directory (`<home>`), e-mail addresses other than the two public ones noted in the script (`<email>`), the account's organization id (`<organization-uuid>`) and the local user name (`<user>`). The sha256 of each raw file is kept next to it (`*.raw.sha256`). The committed transcripts are otherwise unedited, apart from what an agent could have altered in the two records (see the SELinux note in the README).

## Protocol deviations (weak-assertion review)

- **First pass by an AI assistant.** The pre-registered plan has the author apply checklist v1 by hand. Instead, an AI assistant (Claude, not blind: it knew which suite is which) made a first pass for all three suites (`results/weak-assertions-preanalysis.md` and `.json`), and the author reviewed every proposed hit on 2026-10-25 and accepted all of them. Entries the first pass marked as borderline were not counted. The validated count is in `results/weak-assertions.json`.
- **The second LLM rater was not run.** The plan had a blind LLM second rater (labels X, Y, Z). The author chose not to run it, so there is no inter-rater agreement figure.
- **A note outside the count.** Suite B's two wrong-credential tests parse the body with `z.object({ reason: z.string() })`, which strips unknown keys, so the following `expect(body).not.toHaveProperty('token')` cannot fail. Suite B still caught fault 7, because the faulty response had no `reason` and the schema parse threw. This was listed as borderline and is not in the count.
